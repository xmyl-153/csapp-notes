> 一句话定位：把"一切都是位"落到可计算的规则上——**无符号与补码的位模式、转换、扩展截断、加减乘移、内存中的字节序**；对应 CSAPP 第 2 章（Representing and Manipulating Information）2.1–2.3。

## 一、主线：为什么需要它（问题 → 方案 → 代价）

- **问题**：C 语言里的 `int x` 只是"一个整数"的错觉。真实机器上它是一串固定宽度的位，**表示有限 ⇒ 数学性质会丢**。不搞清楚，就写不出 `datalab`，也看不懂编译器生成的移位/加法。
- **方案**：给出两套映射——无符号 `B2U(X)=Σ xᵢ·2ⁱ`（i=0..w−1）和补码 `B2T(X) = −x_{w−1}·2^{w−1} + Σ_{i=0}^{w−2} xᵢ·2ⁱ`（最高位权重为**负**），再定义它们之间的转换、扩展/截断、四则运算。
- **代价**：丢掉的是数学整数的性质——补码加法**不满足有序性**（`TMax + 1 == TMin`，`u > 0` 不能推出 `u+v > v`），乘法可能溢出，`x/2^k` 与 `>>k` 在负数上不等价。要记住**哪些性质还在**：
  - 无符号加法 + 乘法 = **交换环（commutative ring）**；
  - 补码加法 + 乘法 = 与无符号**同构的环（isomorphic ring）**，同构映射就是 casting；
  - 两者都只是"模 2^w 的整数环"的化身。

## 二、知识主干

### 2.1 一切都是位；为什么用二进制

- 每个 bit 是 0 或 1；对位的不同编码/解释决定"计算机做什么"（指令）以及表示什么（数、集合、字符串）。
- 用位是因为**电子实现容易**：可用双稳态元件（bistable element）存储；在噪声大、不精确的导线上**可靠传输**。图上给出 0/1 的电压区间：0 对应约 0.0V–0.2V，1 对应约 0.9V–1.1V，中间是禁止区。
- 二进制计数示例：15213₁₀ = 11101101101101₂；1.20₁₀ = 1.0011001100110011[0011]…₂；1.5213×10⁴ = 1.1101101101101₂ × 2¹³。（原页中下标 2/10 因提取丢失，已按语义还原。）

### 2.2 字节与十六进制

- **Byte（字节）= 8 bits**：二进制 00000000₂–11111111₂，十进制 0₁₀–255₁₀，十六进制 00₁₆–FF₁₆。
- 十六进制用 `0`–`9` 与 `A`–`F`；C 里写作 `0xFA1D37B` 或 `0xfa1d37b`（大小写等价）。**1 个十六进制位 = 4 个二进制位**，所以 hex 是看位模式最省事的形式。

| 1 | 1 | 0001 | 9 | 9 | 1001 |

| 4 | 4 | 0100 | C | 12 | 1100 |

### 2.3 布尔代数与位向量

- George Boole（19 世纪）把逻辑代数化，True→1、False→0：
  - And: `A&B = 1` iff A=1 且 B=1
  - Or: `A|B = 1` iff A=1 或 B=1
  - Not: `~A = 1` iff A=0
  - Xor: `A^B = 1` iff 恰有一个为 1（"或但不都"）
- **General Boolean Algebra**：运算作用在**位向量**上，逐位施加；布尔代数的全部性质都成立。
  - `01101001 & 01010101 = 01000001`
  - `01101001 | 01010101 = 01111101`
  - `01101001 ^ 01010101 = 00111100`
  - `~01010101 = 10101010`

### 2.4 用位向量表示集合（集合运算 ↔ 位运算）

宽度 w 的位向量表示 `{0, …, w−1}` 的子集；`aⱼ = 1` 当且仅当 `j ∈ A`（最右边是第 0 位）。

| 位运算 | 集合运算 | 例子（w=8）|
|---|---|---|
| `&` | 交 Intersection | `01101001 & 01010101 = 01000001` → `{0,6}` |
| `\|` | 并 Union | `01101001 \| 01010101 = 01111101` → `{0,2,3,4,5,6}` |
| `^` | 对称差 Symmetric difference | `01101001 ^ 01010101 = 00111100` → `{2,3,4,5}` |
| `~` | 补 Complement | `~01010101 = 10101010` → `{1,3,5,7}` |

（`01101001` 自身 = `{0,3,5,6}`；`01010101` = `{0,2,4,6}`。）

### 2.5 C 中的位级运算 vs 逻辑运算（**高频易错**）

- 位级：`& | ~ ^`，适用于任何整型（`long/int/short/char/unsigned`），**逐位**作用。
  ```c
  ~0x41  ➙ 0xBE        /* ~01000001₂ = 10111110₂ */
  ~0x00  ➙ 0xFF        /* ~00000000₂ = 11111111₂ */
  0x69 & 0x55 ➙ 0x41   /* 01101001₂ & 01010101₂ = 01000001₂ */
  0x69 | 0x55 ➙ 0x7D   /* 01101001₂ | 01010101₂ = 01111101₂ */
  ```
- 逻辑：`&& || !`，把 0 视为 False、**任何非 0 视为 True**，**永远返回 0 或 1**，并且**短路求值（early termination）**。
  ```c
  !0x41 ➙ 0x00      /* 0x41 非 0 → 真 → 取非得 0 */
  !0x00 ➙ 0x01
  !!0x41 ➙ 0x01     /* 归一化到 0/1 的常用技巧 */
  0x69 && 0x55 ➙ 0x01
  0x69 || 0x55 ➙ 0x01
  p && *p           /* 短路：p 为 NULL 时不会解引用 */
  ```
- 原讲义点名："小心 `&&` vs `&`（以及 `||` vs `|`）……C 编程里最常见的手滑之一。"

### 2.6 移位运算

- 左移 `x << y`：位向量左移 y 位，**左侧多余位丢弃**，右侧**补 0**。
- 右移 `x >> y`：右侧多余位丢弃；分两种——
  - **逻辑右移（logical shift）**：左侧补 0；
  - **算术右移（arithmetic shift）**：左侧**复制最高位（符号位）**。
- **Undefined Behavior**：移位量 `< 0` 或 `≥ 字长`（word size）时行为未定义。
- 例子（原页的移位图，按位移语义整理）：

| 操作 | 二进制结果 |
|---|---|
| `01100010 << 3` | `00010000`（左移丢弃高位，右侧补 0） |
| `01100010 >> 2`（逻辑） | `00011000` |
| `01100010 >> 2`（算术） | `00011000`（符号位为 0，与逻辑一致） |
| `10100010 >> 2`（逻辑） | `00101000` |
| `10100010 >> 2`（算术） | `11101000`（符号位为 1，左侧补 1） |

> 对照表读法：算术右移只对**最高位为 1**（负数）的场合与逻辑右移不同。

### 2.7 整数编码：无符号 vs 补码（Two's Complement）

```c
short int x =  15213;
short int y = -15213;
```

- C 的 `short` 为 2 字节。**Sign Bit**：补码的最高位表示符号，0 非负、1 负。
- 公式：`B2U(X) = Σ_{i=0}^{w−1} xᵢ·2ⁱ`；`B2T(X) = −x_{w−1}·2^{w−1} + Σ_{i=0}^{w−2} xᵢ·2ⁱ`。

| 变量 | 十进制 | Hex | Binary |
|---|---|---|---|
| x | 15213 | 3B 6D | 00111011 01101101 |
| y | −15213 | C4 93 | 11000100 10010011 |

- 权重核对：`y = −32768 + 16384 + 1024 + 256 + 16 + 2 = −15213` ✔

### 2.8 数值范围与不同字长

| 量 | 值 | 位模式 |
|---|---|---|
| UMin | 0 | `000…0` |
| UMax | 2^w − 1 | `111…1` |
| TMin | −2^{w−1} | `100…0` |
| TMax | 2^{w−1} − 1 | `011…1` |
| −1 | −1 | `111…1` |

- w = 16 时：UMax = 65535 (`FF FF`)、TMax = 32767 (`7F FF`)、TMin = −32768 (`80 00`)、−1 = `FF FF`。
- 关键观察：`|TMin| = TMax + 1`（**范围不对称**）；`UMax = 2 * TMax + 1`。

| w | 8 | 16 | 32 | 64 |
|---|---|---|---|---|
| UMax | 255 | 65,535 | 4,294,967,295 | 18,446,744,073,709,551,615 |
| TMax | 127 | 32,767 | 2,147,483,647 | 9,223,372,036,854,775,807 |
| TMin | −128 | −32,768 | −2,147,483,648 | −9,223,372,036,854,775,808 |

- C 里 `#include <limits.h>` 提供 `ULONG_MAX` / `LONG_MAX` / `LONG_MIN` 等常量；**具体取值依平台而定**。

### 2.9 映射的唯一性与可逆性

- 非负值的编码在两套表示里**相同**（equivalence）；每个位模式唯一对应一个整数值，每个可表示整数唯一对应一个位模式（uniqueness）⇒ 映射**可逆**：`U2B(x) = B2U⁻¹(x)`，`T2B(x) = B2T⁻¹(x)`。
- 4 位视角：`0000…0111` 两套解释一致（0..7）；`1000`–`1111` 无符号读作 8..15，补码读作 −8..−1。

### 2.10 有符号 ↔ 无符号的转换（T2U / U2T）与 C 的转换规则

- **核心：保持位模式不变，只重新解释**（T2B → B2U 即 T2U）。视觉上是一张"折叠/平移"的映射：`= ±16`（w=4 时），即 `x < 0` 时 `ux = x + 2^w`。

```
T2U:  ux = x + 2^w   (x < 0)  ;  ux = x  (x ≥ 0)
U2T:  x  = ux − 2^w  (ux ≥ 2^{w−1}) ;  x = ux  (ux < 2^{w−1})
```

- **转换会反转顺序（ordering inversion）**：负数变成大正数。TMin→2^{w−1}，TMax→TMax，−1→UMax。
- C 中：
  - 常量默认是 **signed**；带后缀 `U` 才是无符号（`0U`、`4294967259U`）。
  - **显式强制转换**（casting）`(int) ux`、`(unsigned) ty` 就是 U2T / T2U；
  - **隐式转换**同样发生在赋值和函数调用参数上：`tx = ux;`、`uy = ty;`
- **Casting Surprises（w = 32，TMIN = −2,147,483,648，TMAX = 2,147,483,647）**：表达式中只要混入 unsigned，**signed 会被隐式转成 unsigned**，包括 `< > == <= >=` 比较运算。

| 表达式 | 关系 | 求值结果 |
|---|---|---|
| `0U > -1` | signed −1 → unsigned | **true**（-1 变成 4294967295） |
| `-2147483648 < 2147483647U` | TMin → 2147483648U | **true** |
| `-1 > -2` | 都是 signed | true |
| `(unsigned)-1 > -2` | −2 → 4294967294U | true |
| `2147483647 > (int)2147483648U` | 2147483648U → −2147483648 | **true** |
| `2147483647U < -2147483647-1` | TMin → 2147483648U | **false** |

- 归纳规则：**位模式保持不变、重新解释；效果相当于加/减 2^w；表达式中 signed 与 unsigned 混合时，int 被转成 unsigned！**

### 2.11 扩展与截断

- **符号扩展（Sign Extension）**：把 w 位有符号数变成 w+k 位且值不变——**复制符号位 k 份**：`X' = x_{w−1}, …, x_{w−1}, x_{w−1}, x_{w−2}, …, x₀`。C 在从窄类型转到宽类型时**自动**做符号扩展。

```c
short int x  =  15213;   int ix = (int) x;
short int y  = -15213;   int iy = (int) y;
```

| | 十进制 | Hex | Binary |
|---|---|---|---|
| x | 15213 | 3B 6D | 00111011 01101101 |
| ix | 15213 | 00 00 3B 6D | 00000000 00000000 00111011 01101101 |
| y | −15213 | C4 93 | 11000100 10010011 |
| iy | −15213 | FF FF C4 93 | 11111111 11111111 11000100 10010011 |

- **截断（Truncating）**：直接丢掉高位。无符号：等价于 `mod 2^k`；有符号：类似取模后再重新解释。**小数值得预期结果，大数就未必。**

### 2.12 无符号加法：模 2^w

- 标准加法**忽略进位输出（carry）**，实现模运算：`UAdd_w(u,v) = u + v mod 2^w`。
- 可视化：真和是一个平面；一旦真和 ≥ 2^w 就"绕回"，**最多绕一次**（overflow 区域出现在角落）。
- 数学性质（Abelian group）：封闭、交换、结合、0 是加法单位元、每个元素有加法逆元 `UComp_w(u) = 2^w − u`（u ≠ 0），且 `UAdd_w(u, UComp_w(u)) = 0`。

### 2.13 补码加法：位级行为与无符号完全相同

```c
int s, t, u, v;
s = (int) ((unsigned) u + (unsigned) v);
t = u + v;              /* 必有 s == t */
```

- `TAdd_w` 与 `UAdd_w` **位级行为一致**；真和需要 w+1 位，丢掉最高位后按补码解释。
- 溢出规律（**只可能绕一次**）：
  - 真和 ≥ 2^{w−1} → **正溢出 PosOver**，结果变负；
  - 真和 < −2^{w−1} → **负溢出 NegOver**，结果变正。
- 判据（4 位视角，范围 −8..+7）：两正相加得负 = 正溢出；两负相加得正 = 负溢出。
- 精确刻画：

```
TAdd_w(u,v) = u + v + 2^w     若 u + v < TMin_w          (NegOver)
            = u + v            若 TMin_w ≤ u + v ≤ TMax_w
            = u + v − 2^w      若 TMax_w < u + v          (PosOver)
```

- 性质：与无符号同构（`TAdd_w(u,v) = U2T(UAdd_w(T2U(u), T2U(v)))`），构成一个**群**；逆元为 `TComp_w(u) = −u`（u ≠ TMin_w），而 `TComp_w(TMin_w) = TMin_w`（**TMin 取负等于自己**）。
- **取负 = 取反加一**：`~x + 1 == -x`。推导：`~x + x = 1111…1 = −1`，故 `~x = −1 − x`，两边 +1 即得。例子：`x=15213 (3B 6D)` → `~x = −15214 (C4 92)` → `~x+1 = −15213 (C4 93)`；`x=0` → `~0 = −1 (FF FF)` → `~0+1 = 0`。

### 2.14 乘法

- 真积可能需要 **2w 位**：
  - 无符号：`0 ≤ x*y ≤ (2^w − 1)² = 2^{2w} − 2^{w+1} + 1`，最多 2w 位；
  - 补码最小值（负）：`x*y ≥ (−2^{w−1})(2^{w−1}−1) = −2^{2w−2} + 2^{w−1}`，最多 2w−1 位；
  - 补码最大值（正）：`x*y ≤ (−2^{w−1})² = 2^{2w−2}`，最多 2w 位，且**只在 (TMin_w)² 这一种情况**达到。
- 要保留精确结果就得不断加宽字长——这由软件完成，即"**任意精度（arbitrary precision）算术包**"。
- C 的乘法：**丢弃高 w 位**（无符号 `UMult_w(u,v) = u·v mod 2^w`）；有符号与无符号的高位不同，但**低位完全相同**：`TMult_w` 与 `UMult_w` 在低 w 位上一致。

### 2.15 用移位做乘除 2 的幂

- 左移 `u << k` = `u * 2^k`（有无符号都一样）。
  ```c
  u << 3            ==  u * 8
  (u << 5) - (u << 3) ==  u * 24     /* 24 = 8 + 16 = 2^3 + 2^4 */
  ```
- 原因：真积需要 w+k 位，丢掉高 k 位后正好等于 `u·2^k mod 2^w`。多数机器移位+加法比乘法快，**编译器会自动生成这种代码**。

- **无符号除以 2 的幂**：`u >> k` 给出 `⌊ u / 2^k ⌋`，用**逻辑右移**。

| 表达式 | 除法（精确） | 计算结果 | Hex | Binary |
|---|---|---|---|---|
| x = 15213 | 15213 | 15213 | 3B 6D | 00111011 01101101 |
| x >> 1 | 7606.5 | 7606 | 1D B6 | 00011101 10110110 |
| x >> 4 | 950.8125 | 950 | 03 B6 | 00000011 10110110 |
| x >> 8 | 59.4257813 | 59 | 00 3B | 00000000 00111011 |

- **有符号除以 2 的幂**：`x >> k` 给出 `⌊ x / 2^k ⌋`（**向下取整**），用**算术右移**，**负数时舍入方向是错的**（C 的除法向 0 取整）。

| 表达式 | 除法（精确） | 计算结果 | Hex | Binary |
|---|---|---|---|---|
| y = −15213 | −15213 | −15213 | C4 93 | 11000100 10010011 |
| y >> 1 | −7606.5 | **−7607** | E2 49 | 11100010 01001001 |
| y >> 4 | −950.8125 | **−951** | FC 49 | 11111100 01001001 |
| y >> 8 | −59.4257813 | **−60** | FF C4 | 11111111 11000100 |

- **修正办法（biasing）**：想要 `⌈ x / 2^k ⌉`（向 0 取整），先给被除数加偏置 `2^k − 1`：
  - 原讲义写作 `x >> k`，C 写法为 `(x + (1<<k) - 1) >> k`；
  - 不需舍入的情况偏置无影响，需舍入时偏置刚好把结果加 1。

```c
long idiv8(long x) {
    if (x < 0) x += 7;     /* 偏置 2^3 - 1 = 7 */
    return x >> 3;         /* 算术右移 */
}
```

```asm
    testq %rax, %rax       # 测试 x
    js    L4               # x < 0 则跳转
L3: sarq  $3, %rax         # 算术右移 3 位
    ret
L4: addq  $7, %rax         # x += 7
    jmp   L3
```

- 对照：无符号版本只需一条逻辑右移。

```asm
    shrq $3, %rax          # 逻辑右移，等价 x/8（无符号）
```

- 编译器为常量乘法生成的代码（`x*12`）：
  ```asm
  leaq (%rax,%rax,2), %rax   # t = x + x*2 = 3x
  salq $2, %rax              # return t << 2 = 12x
  ```

### 2.16 运算总结规则（原讲义 Basic Rules）

- **加法**：无符号/有符号都是"正常相加后截断"，位级同一操作；无符号 = 模 2^w 加法；有符号 = 改版模 2^w 加法（结果落在合法范围），数学上相当于"真和 ± 2^w"。
- **乘法**：同样"正常相乘后截断"，位级低 w 位相同；无符号 = 模 2^w 乘法；有符号 = 改版模 2^w 乘法。
- **左移**：有无符号都是乘 2^k，**总是逻辑移位**。
- **右移**：无符号用逻辑移位 ⇒ 除以 2^k 并**向 0 取整**；有符号用算术移位 ⇒ 正数向 0 取整、**负数向远离 0 的方向取整（即向下）**，需要 biasing 修正。

### 2.17 什么时候该用 unsigned（以及怎么用错）

- **不要在没有理解后果时用**。经典错误：

```c
/* 错误 1：无符号循环变量永远不会 < 0 */
unsigned i;
for (i = cnt-2; i >= 0; i--)      /* i >= 0 恒真 ⇒ 死循环 */
    a[i] += a[i+1];

/* 错误 2：隐式转换让比较失效 */
#define DELTA sizeof(int)
int i;
for (i = CNT; i-DELTA >= 0; i -= DELTA)   /* i-DELTA 是 size_t（无符号） */
    . . .                                  /* 永远 >= 0 */
```

- **正确的倒计数写法**：利用"无符号加法保证是模运算"这一 C 标准保证（`0 - 1 ⇒ UMax`）：

```c
unsigned i;
for (i = cnt-2; i < cnt; i--)     /* 绕回到 UMax 后仍 < cnt，循环终止 */
    a[i] += a[i+1];
```

- **更好的写法**：用 `size_t`（长度 = 字长的无符号类型），即便 `cnt = UMax` 也正确；但要留神 `cnt` 是有符号且为负的情况。（参考 Robert Seacord, *Secure Coding in C and C++*）
- **该用无符号的场合**：做模运算（多精度算术 multiprecision arithmetic）、用位表示集合（需要逻辑右移、不做符号扩展）。

### 2.18 内存中的表示：地址、字长、字节序

- 程序用**地址**引用数据：可以把内存想成一个巨大的字节数组，地址是下标，**指针变量存放地址**。系统为每个**进程**提供私有地址空间 ⇒ 程序可以破坏自己的数据，但动不了别的进程的。
- **Machine Word（机器字）**：整数型数据和地址的标称大小。曾经多为 32 位（4 字节）⇒ 地址上限 4GB（2³² 字节）；越来越常见的是 64 位 ⇒ 理论可寻址 18 EB = 18.4 × 10¹⁸ 字节。机器仍支持多种数据格式，都是字长的**分数或倍数**，但**总是整数个字节**。
- 地址指定字节位置：字的地址 = 第一个字节的地址；相邻字的地址差 4（32 位）或 8（64 位）。
- **C 数据类型典型大小**（原页表格，表头为 "Typical 32-bit / Typical 64-bit x86-64"；原文数字因提取丢失，按 CSAPP 第 2 版/第 3 版通用值补齐：char 1/1，short 2/2，int 4/4，long 4/**8**，float 4/4，double 8/8，long double −/10 或 16，pointer 4/**8**）：

| C 类型 | 32-bit | x86-64 |
|---|---|---|
| char | 1 | 1 |
| short | 2 | 2 |
| int | 4 | 4 |
| long | 4 | **8** |
| float | 4 | 4 |
| double | 8 | 8 |
| long double | − | 10/16 |
| pointer | 4 | **8** |

- **字节序（Byte Ordering）**：
  - **Big Endian（大端）**：Sun、PPC Mac、**Internet**；**最低有效字节在最高地址**。
  - **Little Endian（小端）**：**x86、ARM**（Android/iOS/Windows）；**最低有效字节在最低地址**。
- 例子：4 字节变量 `x = 0x01234567`，`&x = 0x100` ⇒ 大端在 `0x100..0x103` 依次存 `01 23 45 67`（**最高有效字节在最低地址**）；小端依次存 `67 45 23 01`。
- 整数实例：

| 变量 | 十进制 | Hex | 小端字节（低→高） | 大端字节（低→高） |
|---|---|---|---|---|
| `int A = 15213;` | 15213 | 3B 6D | `6D 3B 00 00` | `00 00 3B 6D` |
| `int B = -15213;` | −15213 | C4 93 | `93 C4 FF FF` | `FF FF C4 93` |
| `long C = 15213;`（x86-64） | 15213 | 3B 6D | `6D 3B 00 00 00 00 00 00` | `00 … 3B 6D` |

- **打印字节表示**：

```c
typedef unsigned char *pointer;   /* 把指针转成 unsigned char* 就能按字节数组看数据 */

void show_bytes(pointer start, size_t len) {
    size_t i;
    for (i = 0; i < len; i++)
        printf("%p\t0x%.2x\n", start+i, start[i]);
    printf("\n");
}

int a = 15213;
show_bytes((pointer) &a, sizeof(int));
/* Linux x86-64 输出（小端）：地址最低处是 6d，然后是 3b，再是 00 00 */
/* 0x7fffb7f71dbc  6d
   0x7fffb7f71dbd  3b
   0x7fffb7f71dbe  00
   0x7fffb7f71dbf  00   */
```

  - printf 指示符：`%p` 打印指针，`%x` 打印十六进制。
- **指针表示**：不同编译器/机器给对象分配的位置不同，**每次运行都可能不同**（栈地址随机化）。
- **字符串表示**：C 字符串是字符数组，每字符用 **ASCII**（字符集的 7 位标准编码）；字符 `"0"` 的码是 `0x30`，数字 i 的码是 `0x30 + i`；字符串以 **null 结尾**（最后一个字符是 0）。`char S[6] = "18213";` ⇒ 字节 `31 38 32 31 33 00`。**字符串不受字节序影响**（兼容性由 ASCII 保证）。

### 2.19 代码安全实例

**例 1：内核缓冲区拷贝（类似 FreeBSD `getpeername` 实现中的真实缺陷）**

```c
/* 内核中保存用户可访问数据的内存区 */
#define KSIZE 1024
char kbuf[KSIZE];

/* 最多从内核区拷贝 maxlen 字节到用户缓冲区 */
int copy_from_kernel(void *user_dest, int maxlen) {
    /* 字节数 len 取缓冲区大小与 maxlen 中的较小者 */
    int len = KSIZE < maxlen ? KSIZE : maxlen;
    memcpy(user_dest, kbuf, len);
    return len;
}

/* 正常用法 */
#define MSIZE 528
void getstuff() {
    char mybuf[MSIZE];
    copy_from_kernel(mybuf, MSIZE);   /* len = 528，安全 */
    printf("%s\n", mybuf);
}
```

```c
/* 恶意用法：传负数 */
copy_from_kernel(mybuf, -MSIZE);      /* maxlen = -528 < KSIZE ⇒ len = -528 */
```

- 缺陷点：`maxlen` 是 **int（有符号）**，但 `memcpy` 的第三个参数是 `size_t`（无符号）：`void *memcpy(void *dest, void *src, size_t n);`。负数 → 转成巨大的无符号数 → **拷贝远超用户缓冲区的数据**（内核内存泄漏 / 栈溢出）。
- 教训：**signed/unsigned 转换是安全漏洞的主要来源之一**，"总有聪明人在找程序里的漏洞"。

**例 2：SUN XDR 库的乘法溢出**

```c
void* copy_elements(void *ele_src[], int ele_cnt, size_t ele_size) {
    /* 为 ele_cnt 个对象分配缓冲区，每个 ele_size 字节，并从 ele_src 指定的位置拷贝 */
    void *result = malloc(ele_cnt * ele_size);
    if (result == NULL)
        return NULL;                       /* malloc 失败 */
    void *next = result;
    int i;
    for (i = 0; i < ele_cnt; i++) {
        memcpy(next, ele_src[i], ele_size);   /* 拷贝第 i 个对象 */
        next += ele_size;                     /* 指针移到下一块内存 */
    }
    return result;
}
```

- 漏洞：`ele_cnt = 2^20 + 1`、`ele_size = 4096 = 2^12` 时，真实乘积需要 33 位，而 `malloc` 的参数是 **size_t（32 位平台上会回绕）**，分配出来的缓冲区远小于实际要拷贝的数据量 ⇒ 堆溢出。
- 加固方向：在乘法/分配前**显式检查溢出**（如 `ele_cnt` 是否超过 `SIZE_MAX/ele_size`）。

## 三、必记结论与数字

| 结论 | 内容 |
|---|---|
| 字节 | 1 byte = 8 bits；hex 一位 = 4 bits |
| B2U | `Σ xᵢ·2ⁱ`（i=0..w−1） |
| B2T | `−x_{w−1}·2^{w−1} + Σ xᵢ·2ⁱ`（i=0..w−2） |
| 范围关系 | `|TMin| = TMax + 1`；`UMax = 2*TMax + 1` |
| w=16 常数 | UMax 65535 = `FF FF`；TMax 32767 = `7F FF`；TMin −32768 = `80 00`；−1 = `FF FF` |
| 转换 | 保持位模式、重新解释；`x<0` 时 `ux = x + 2^w`；混合表达式中 **signed → unsigned** |
| 扩展 | 有符号复制符号位，无符号补 0 |
| 截断 | 丢高位；无符号 = `mod 2^k` |
| 加法 | `UAdd_w = (u+v) mod 2^w`；`TAdd_w` 与 `UAdd_w` 位级相同；溢出最多绕一次 |
| 取负 | `~x + 1 == -x`；`-TMin == TMin` |
| 乘法 | 丢高 w 位；有无符号**低 w 位相同**；真积最多 2w 位 |
| 移位 | `u << k = u * 2^k`；`u >> k`（逻辑）= `⌊u/2^k⌋`；算术右移对负数舍入方向错，需 `+ (1<<k)-1` 偏置 |
| 字节序 | 小端（x86/ARM）：最低有效字节在最低地址；大端（Sun/Internet）：反之 |
| 字长 | 32 位 ⇒ 4GB（2³²）；64 位 ⇒ 18 EB ≈ 18.4×10¹⁸ |
| 安全 | `memcpy` 的 n 是 `size_t`；`malloc(cnt*size)` 会回绕 |

## 四、易错点 / 陷阱

1. **`&&` vs `&`、`||` vs `|`**：原讲义称"最常见的 oopsies 之一"。逻辑运算返回 0/1 且短路，位运算逐位且不短路。`p && *p` 能防空指针解引用，`p & *p` 不能。
2. **混用 signed/unsigned 的比较**：`-1 > 0U` 为真；循环 `for (i = cnt-2; i >= 0; i--)` 在 `unsigned i` 下是死循环。凡是"无符号量 < 0"的判断都是恒假，编译器可能直接优化掉。
3. **`u >> k` 做除法只对无符号安全**：有符号负数必须 biasing（`(x + (1<<k) - 1) >> k`），否则 `-15213 >> 1` 得 −7607 而不是 −7606。
4. **移位量越界是 UB**：移位量 `< 0` 或 `≥` 字长，结果未定义（不是"循环移位"）。
5. **`-TMin == TMin`**：补码范围不对称的直接后果，`|x|` / `-x` 在 TMin 上失效。
6. **符号扩展 vs 零扩展**：`short` → `int` 在有符号时复制符号位（`C4 93` → `FF FF C4 93`），无符号时补 0；把 `char` 当无符号用时要显式写 `unsigned char`。
7. **字节序陷阱**：`show_bytes` 在小端机上打印出的字节顺序与手写 hex 相反；网络字节序是大端。字符串/字节数组不受字节序影响。
8. **溢出/转换是安全漏洞**：`int maxlen` 传给 `size_t n`（负数变巨大）；`malloc(ele_cnt * ele_size)` 回绕（分配不足、随后堆溢出）。
9. **`x * x >= 0` 并不总成立**（补码 `15213 * 30426 == -10030`，16 位字长）；`x > 0 && y > 0 ⇒ x + y > 0` 在 `TMax + 1 == TMin` 时失效。整数 puzzle 的原题（`ux >= 0` 恒真、`ux >> 3 == ux/8` 恒真、`x >> 3 == x/8` 在 x<0 时**假**、`(x|-x)>>31 == -1` 在 x=0 时**假**）都来自这一组性质。
10. **`~0 + 1 == 0`**：不要看到 `~x` 就以为是"取负"。
