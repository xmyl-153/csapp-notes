# 浮点数（15-213 04-float，第 4 讲，2015-09-10）

> 一句话定位：从"小数二进制"出发，定义 **IEEE 754** 的位级格式（规格化 / 非规格化 / 特殊值）、舍入与浮点加减乘的算法及其代数性质；对应 CSAPP 第 2 章 2.4（Floating Point）。

## 一、主线：为什么需要它（问题 → 方案 → 代价）

- **问题**：只要一个"二进制小数点"位置，能表示的数就被限制成 `x/2^k`，而且量级范围极窄——很小的数和很大的数都表示不了。
- **方案**：**IEEE Standard 754**（1985 年确立，成为浮点算术的统一标准，此前各家格式五花八门；所有主流 CPU 都支持）。它把数写成 `(−1)^s M 2^E`，让**小数点位置随指数浮动**，并用工程化的规则把 rounding / overflow / underflow 定义清楚。
- **代价**：
  - 该标准由**数值分析学家主导**（而非硬件设计师）制定 ⇒ 语义漂亮，但**在硬件上做快很难**；
  - 只在 `M × 2^E` 这种形式上精确，其余有理数是**循环位模式**（1/3、1/5、1/10 都表示不精确）；
  - **违反结合律/分配律**，给编译器与认真做数值的程序员制造麻烦。

## 二、知识主干

### 2.1 小数二进制数（Fractional Binary Numbers）

- 二进制小数点右侧的位表示 **2 的负幂**：`2ⁱ … 2¹ 2⁰ . 2⁻¹ 2⁻² 2⁻³ … 2⁻ʲ`，位串 `bᵢ bᵢ₋₁ … b₂ b₁ b₀ . b₋₁ b₋₂ b₋₃ … b₋ⱼ` 表示有理数 `Σ bₖ·2^k`。
- 举例：`1011.101₂ = 11.625`（原页 p.3 提出的问题：`1011.101₂` 是多少）。

| 值 | 表示 |
|---|---|
| 5 3/4 | `101.11₂` |
| 2 7/8 | `010.111₂` |
| 1 7/16 | `001.0111₂` |

- 观察：
  - 除以 2 = 右移一位（对无符号数）；乘以 2 = 左移一位；
  - `0.111111…₂` 这样的数**恰好小于 1.0**：`1/2 + 1/4 + 1/8 + … + 1/2ⁱ + … ➙ 1.0`，记作 `1.0 − ε`。
- **两个根本限制**：
  1. 只能精确表示 `x/2^k` 形式的数，其他有理数位模式循环：
     - `1/3 = 0.0101010101[01]…₂`
     - `1/5 = 0.001100110011[0011]…₂`
     - `1/10 = 0.0001100110011[0011]…₂`
  2. w 位里**只能有一个固定的小数点位置** ⇒ 可表示范围有限（很小 / 很大的数都覆盖不到）。

### 2.2 IEEE 浮点表示

数值形式：

```
v = (−1)^s × M × 2^E
```

- 符号位 s 决定正负；**significand（尾数）M 通常是 [1.0, 2.0) 的小数值**；指数 E 以 2 的幂加权该值。
- 编码（MSB 是符号位 s，然后是 exp 域和 frac 域）：
  - `exp` 域**编码** E，但**不等于** E（有偏置）；
  - `frac` 域**编码** M，但**不等于** M（有隐含前导位）。

```
| s |   exp   |    frac    |
```

| 精度 | 总位数 | exp 位数 | frac 位数 |
|---|---|---|---|
| Single precision | 32 | 8 | 23 |
| Double precision | 64 | 11 | 52 |
| Extended precision（仅 Intel） | 80 | 15 | 63 或 64 |

### 2.3 规格化值（"Normalized" Values）

- **条件**：`exp ≠ 000…0` 且 `exp ≠ 111…1`。
- **指数编码为偏置值（biased）**：`E = Exp − Bias`
  - `Exp` = exp 域的**无符号值**；
  - `Bias = 2^{k−1} − 1`，k 为指数位数；
  - 单精度：Bias = **127**（Exp: 1…254，E: −126…127）；
  - 双精度：Bias = **1023**（Exp: 1…2046，E: −1022…1023）。
- **尾数带隐含前导 1**：`M = 1.xxx…x₂`，其中 `xxx…x` 是 frac 域的位。
  - frac = `000…0` 时最小：`M = 1.0`；
  - frac = `111…1` 时最大：`M = 2.0 − ε`；
  - 相当于**白赚一个前导位**（get extra leading bit for "free"）。

### 2.4 规格化编码实例：`float F = 15213.0;`

```
15213₁₀ = 11101101101101₂ = 1.1101101101101₂ × 2^13
```

- 尾数：`M = 1.1101101101101₂` ⇒ `frac = 11011011011010000000000₂`（补足 23 位）
- 指数：`E = 13`，`Bias = 127` ⇒ `Exp = 140 = 10001100₂`
- 结果：`0 10001100 11011011011010000000000`（s=0，exp=10001100，frac=1101101101101 后接 0 到 23 位）

### 2.5 非规格化值（Denormalized Values）

- **条件**：`exp = 000…0`。
- **指数值：`E = 1 − Bias`**（注意不是 `0 − Bias`）。
- **尾数隐含前导 0**：`M = 0.xxx…x₂`。
- 两种情况：
  - `exp = 000…0, frac = 000…0` ⇒ **零值**；注意有 `+0` 和 `−0` **两个不同的值**（why? 因为符号位独立，且需要保持"符号连续"、让 `1/−0 = −∞` 等语义自然）；
  - `exp = 000…0, frac ≠ 000…0` ⇒ **最接近 0.0 的数**，且是**等间距的（equispaced）**。

### 2.6 特殊值

- **条件**：`exp = 111…1`。
  - `exp = 111…1, frac = 000…0` ⇒ **∞**：表示溢出（overflow）的运算结果，有正有负。例：`1.0/0.0 = −1.0/−0.0 = +∞`，`1.0/−0.0 = −∞`。
  - `exp = 111…1, frac ≠ 000…0` ⇒ **NaN（Not-a-Number）**：无法确定数值的场合，例 `sqrt(−1)`、`∞ − ∞`、`∞ × 0`。

### 2.7 编码可视化

数轴（从小到大）：`−∞ | −Normalized | −Denorm | −0 | +0 | +Denorm | +Normalized | +∞`，两侧 `NaN` 与 `±∞` 并列。**整数 0 的位模式（全 0）就是浮点 +0。**

### 2.8 完整小例子：8 位浮点格式

格式：符号位 1 位（MSB）+ 指数 **4 位，Bias = 7** + frac **3 位**；与 IEEE 格式同构（含规格化、非规格化、0、NaN、∞）。

| s exp frac | E | Value | 说明 |
|---|---|---|---|
| `0 0000 000` | −6 | 0 | 零 |
| `0 0000 001` | −6 | 1/8 × 1/64 = 1/512 | 最接近 0 的正数 |
| `0 0000 010` | −6 | 2/8 × 1/64 = 2/512 | |
| … | −6 | … | |
| `0 0000 110` | −6 | 6/8 × 1/64 = 6/512 | |
| `0 0000 111` | −6 | 7/8 × 1/64 = 7/512 | 最大的非规格化数 |
| `0 0001 000` | −6 | 8/8 × 1/64 = 8/512 | 最小的规格化数 |
| `0 0001 001` | −6 | 9/8 × 1/64 = 9/512 | |
| … | −1 | … | |
| `0 0110 110` | −1 | 14/8 × 1/2 = 14/16 | |
| `0 0110 111` | −1 | 15/8 × 1/2 = 15/16 | 小于 1 中最接近 1 的 |
| `0 0111 000` | 0 | 8/8 × 1 = 1 | 1.0 |
| `0 0111 001` | 0 | 9/8 × 1 = 9/8 | 大于 1 中最接近 1 的 |
| `0 0111 010` | 0 | 10/8 × 1 = 10/8 | |
| … | … | … | |
| `0 1110 110` | 7 | 14/8 × 128 = 224 | |
| `0 1110 111` | 7 | 15/8 × 128 = 240 | 最大的规格化数 |
| `0 1111 000` | n/a | inf | 无穷 |

- 换算口径：`v = (−1)^s M 2^E`，十进制规格化 `E = Exp − Bias`，非规格化 `E = 1 − Bias`。
- **注意非规格化 → 规格化的平滑过渡**：`7/512` 的下一个就是 `8/512`，无缝衔接——这正是非规格化值存在的意义。

### 2.10 IEEE 编码的特殊性质

- **浮点零 = 整数零**：位模式全 0。
- **几乎可以用无符号整数比较来比较浮点**：
  - 必须先比较符号位；
  - 必须考虑 `−0 = 0`；
  - **NaN 有问题**：按位模式它大于任何其他值，但比较应该给出什么结果？（不可比）
  - 除此之外没问题：非规格化 vs 规格化、规格化 vs 无穷，位模式的大小顺序与数值顺序一致。

### 2.11 浮点运算的基本思路

```
x +_f y = Round(x + y)
x ×_f y = Round(x × y)
```

- 三步：**先算精确结果 → 再让它适配目标精度 → 溢出（指数过大）或舍入（适配 frac）**。
- 关键心法：**可以"假装"以无限精度计算然后舍入**——这是独立于实现的推理方式。

### 2.12 舍入（Rounding）

四种舍入模式（用美元角分举例，$1.40 / $1.60 / $1.50 / $2.50 / −$1.50）：

| 模式 | $1.40 | $1.60 | $1.50 | $2.50 | −$1.50 |
|---|---|---|---|---|---|
| Towards zero（向 0） | $1 | $1 | $1 | $2 | −$1 |
| Round down（−∞，向下） | $1 | $1 | $1 | $2 | −$2 |
| Round up（+∞，向上） | $2 | $2 | $2 | $3 | −$1 |
| **Nearest Even（默认）** | $1 | $2 | $2 | $2 | −$2 |

- **Round-To-Even 是默认模式**：
  - 不写汇编就拿不到其它模式；
  - **其它三种在统计上都有偏**：一组正数求和会系统性地高估或低估；
  - 规则：恰好在中点时，**让最低有效位变成偶数**。
- 十进制例子（舍入到百分位）：`7.8949999 ➙ 7.89`（不到一半）、`7.8950001 ➙ 7.90`（超过一半）、`7.8950000 ➙ 7.90`（正好一半，进位后是偶数）、`7.8850000 ➙ 7.88`（正好一半，舍去后是偶数）。
- **二进制情形**：
  - 最低有效位为 0 就是"偶"；
  - 舍入位置右侧恰好是 `100…₂` 时才算"正好一半"。
- 例子（舍入到最近的 1/4，即小数点后 2 位）：

| 值 | 二进制 | 舍入结果 | 动作 | 舍入后的值 |
|---|---|---|---|---|
| 2 3/32 | `10.00011₂` | `10.00₂` | (< 1/2，舍) | 2 |
| 2 3/16 | `10.00110₂` | `10.01₂` | (> 1/2，入) | 2 1/4 |
| 2 7/8 | `10.11100₂` | `11.00₂` | (= 1/2，入) | 3 |
| 2 5/8 | `10.10100₂` | `10.10₂` | (= 1/2，舍) | 2 1/2 |

### 2.13 浮点乘法

```
(−1)^{s1} M1 2^{E1} × (−1)^{s2} M2 2^{E2}
```

- 精确结果 `(−1)^s M 2^E`：符号 `s = s1 ^ s2`；尾数 `M = M1 × M2`；指数 `E = E1 + E2`。
- **修正（Fixing）**：
  1. 若 `M ≥ 2`，把 M 右移、指数加 1；
  2. 若 E 超出范围 ⇒ **溢出**；
  3. 把 M 舍入到 frac 精度。
- 实现上**最繁重的活是尾数相乘**。
- 注意：图上的"discard k bits"只适用于 `2^k` 这类特例；一般乘法是乘积的高位溢出 + 舍入。

### 2.14 浮点加法

```
(−1)^{s1} M1 2^{E1} + (−1)^{s2} M2 2^{E2}      （设 E1 > E2）
```

- **对齐（align）小数点是关键**：指数小的那个尾数要右移 `E1 − E2` 位，然后做带符号的加法得到一个有符号的 M，指数结果取 `E1`。
- **修正**：
  1. `M ≥ 2` ⇒ 右移 M、指数加 1；
  2. `M < 1` ⇒ 左移 M 共 k 位、指数减 k（这步叫**后规格化 Postnormalize**）；
  3. E 超范围 ⇒ 溢出；
  4. 舍入 M 到 frac 精度。
- 直觉后果：**对齐会把小数"挤出去"**——这就是"小量被大量吞掉"的根源。

### 2.15 浮点运算的数学性质

**FP 加法 vs Abelian Group**：

| 性质 | 成立？ |
|---|---|
| 封闭？ | Yes（但可能产生 ∞ 或 NaN） |
| 交换？ | Yes |
| **结合？** | **No**（溢出 + 舍入不精确）：`(3.14+1e10)-1e10 = 0`，而 `3.14+(1e10-1e10) = 3.14` |
| 0 是加法单位元？ | Yes |
| 每个元素有加法逆元？ | Almost（∞ 与 NaN 除外） |
| 单调性 `a ≥ b ⇒ a+c ≥ b+c`？ | Almost（∞ 与 NaN 除外） |

**FP 乘法 vs Commutative Ring**：

| 性质 | 成立？ |
|---|---|
| 封闭？ | Yes（可能产生 ∞ 或 NaN） |
| 交换？ | Yes |
| **结合？** | **No**：`(1e20*1e20)*1e-20 = inf`，而 `1e20*(1e20*1e-20) = 1e20` |
| 1 是乘法单位元？ | Yes |
| **分配？** | **No**：`1e20*(1e20-1e20) = 0.0`，而 `1e20*1e20 − 1e20*1e20 = NaN` |
| 单调性 `a ≥ b & c ≥ 0 ⇒ a*c ≥ b*c`？ | Almost（∞ 与 NaN 除外） |

### 2.16 C 中的浮点

- C 只保证两个级别：`float` = single precision，`double` = double precision。
- **转换/强制类型转换会改变位表示**：
  - `double`/`float` → `int`：**截断小数部分**（相当于向 0 舍入）；超出范围或 NaN 时**结果未定义**（一般会置成 `TMin`）；
  - `int` → `double`：**精确转换**，只要 int 的字长 ≤ 53 位；
  - `int` → `float`：按当前舍入模式**舍入**。
- C 浮点谜题（`int x; float f; double d;` 且保证 d、f 都不是 NaN）：
  - `x == (int)(float) x` —— **假**（float 尾数只有 23 位，x 大于 2²⁴ 就丢位）；
  - `x == (int)(double) x` —— **真**（double 尾数 52 位，覆盖所有 int32）；
  - `f == (float)(double) f` —— 真；`d == (double)(float) d` —— **假**（double 精度更高，转 float 丢位）；
  - `f == -(-f)` —— 真；`2/3 == 2/3.0` —— **假**（左边是整数除法得 0，右边约 0.667）；
  - `d < 0.0 ⇒ (d*2) < 0.0` —— 真（乘 2 精确，只改指数）；`d > f ⇒ -f > -d` —— 真；
  - `d * d >= 0.0` —— 真；`(d+f)-d == f` —— **假**（对齐导致 f 被舍掉，见 2.15）。

### 2.17 附加内容（Additional Slides）

**从 8 位无符号数构造小浮点数的三步流程**：`Normalize → Round → Postnormalize`。

1. **规格化**（让数变成 `1.xxxxx` 形式，左移多少位就相应减指数）：

| Value | Binary | Fraction | Exponent |
|---|---|---|---|
| 10000000 | `1.0000000` | 1.000 | 7 |
| 00001101 | `1.1010000` | 1.101 | 3 |
| 00010001 | `1.0001000` | 1.000 | 4 |
| 00010011 | `1.0011000` | 1.001 | 4 |
| 10001010 | `1.0001010` | 1.000 | 7 |
| 00111111 | `1.1111100` | 1.111 | 5 |

2. **舍入：Guard / Round / Sticky 三位法**（原页布局 `1.BBGRXXX`）：
   - **Guard bit**：结果的最低有效位（保留部分的最后一位）；
   - **Round bit**：被丢弃的**第 1 位**；
   - **Sticky bit**：其余被丢弃位的**或（OR）**；
   - 规则：`Round=1, Sticky=1 ⇒ > 0.5` 进位；`Guard=1, Round=1, Sticky=0 ⇒ 正好一半，向偶舍入`。

| C 值 | Fraction | GRS | Incr? | Rounded |
|---|---|---|---|---|
| 00010001 | `1.0001000` | 100 | N | 1.000 |
| 00010011 | `1.0011000` | 110 | Y | 1.010 |
| 10001010 | `1.0001010` | 010 | Y | 1.001 |
| 00111111 | `1.1111100` | 111 | Y | **10.000**（舍入导致进位溢出） |

3. **后规格化**：舍入可能导致溢出（`1.111… → 10.000`），处理办法是**右移一位并把指数加 1**。

**有意思的数（Interesting Numbers）**（`{single, double}` 两套取值）：

| 描述 | exp | frac | 数值 |
|---|---|---|---|
| Zero | `00…00` | `00…00` | 0.0 |
| Smallest Pos. Denorm. | `00…00` | `00…01` | `2^−{23,52} × 2^−{126,1022}`；single ≈ **1.4 × 10⁻⁴⁵**，double ≈ **4.9 × 10⁻³²⁴** |
| Largest Denormalized | `00…00` | `11…11` | `(1.0 − ε) × 2^−{126,1022}`；single ≈ **1.18 × 10⁻³⁸**，double ≈ **2.2 × 10⁻³⁰⁸** |
| Smallest Pos. Normalized | `00…01` | `00…00` | `1.0 × 2^−{126,1022}`（刚好大于最大非规格化数） |
| One | `01…11` | `00…00` | 1.0 |
| Largest Normalized | `11…10` | `11…11` | `(2.0 − ε) × 2^{127,1023}`；single ≈ **3.4 × 10³⁸**，double ≈ **1.8 × 10³⁰⁸** |

## 三、必记结论与数字

- `v = (−1)^s M 2^E`；规格化：`E = Exp − Bias`、`M = 1.xxx…x₂`；非规格化：`E = 1 − Bias`、`M = 0.xxx…x₂`。
- **Bias**：单精度 **127**、双精度 **1023**；`Bias = 2^{k−1} − 1`。
- 位宽：single = 1 + **8** + **23**；double = 1 + **11** + **52**；extended（Intel）= 1 + 15 + 63/64。
- exp 域语义：`000…0` = 非规格化（frac=0 时是 ±0）；`111…1` = ∞ / NaN；其余为规格化。
- 单精度指数范围：Exp 1…254 ⇒ E ∈ [−126, 127]；双精度：Exp 1…2046 ⇒ E ∈ [−1022, 1023]。
- 边界数值：最大规格化 ≈ **3.4×10³⁸**（single）/ **1.8×10³⁰⁸**（double）；最小正规格化 ≈ **1.18×10⁻³⁸**（single）/ **2.2×10⁻³⁰⁸**（double）；最小正非规格化 ≈ **1.4×10⁻⁴⁵**（single）/ **4.9×10⁻³²⁴**（double）。
- 默认舍入 = **Nearest Even**；`x +_f y = Round(x+y)`、`x ×_f y = Round(x×y)`。
- 浮点**不满足结合律、不满足分配律**；加法不是严格单位元/逆元完备的（∞、NaN 除外）。
- `2.0 − ε`：frac 全 1 时的最大尾数；`1.0 − ε`：`0.111…₂`。

## 四、易错点 / 陷阱

1. **`float` 精度只有 23 位尾数**：任何绝对值 > 2²⁴ 的 int 转 float 都可能丢位 ⇒ `x == (int)(float) x` 不成立；`double` 尾数 52 位才能无损容纳 int32。
2. **`(double)(float) d != d`**：往回转加精度不等于原来的值——浮点转换是**有损**的，不是"换个类型接着用"。
3. **结合律/分配律失效**：重排浮点表达式会改变结果（`(3.14+1e10)-1e10 = 0`）。这也是编译器不敢做代数重排的原因。
4. **`d < 0 ⇒ d*2 < 0` 成立，但 `(d+f)-d == f` 不成立**：乘 2 只改指数（精确），加减法要对齐小数点并舍入。
5. **`2/3 == 2/3.0` 是假**：左边是整数除法恒为 0。整数/浮点混写要显式写 `2.0/3`。
6. **非规格化的指数是 `1 − Bias` 而不是 `0 − Bias`**：这是为了与最小规格化数平滑衔接（`7/512 → 8/512`）。
7. **`+0` 与 `−0` 是两个不同位模式但比较相等**；`1.0/0.0 = +∞`、`1.0/−0.0 = −∞`——除以零不是崩溃而是 ∞/NaN。
8. **NaN 参与比较永远为假**（包括 `NaN == NaN`），且按位模式排序时它比任何值都大——不能直接用无符号整数比较代替浮点比较。
9. **舍入方向默认是"向偶"不是"四舍五入"**：恰好中点时看最低有效位的奇偶（`7.8950000 → 7.90`，`7.8850000 → 7.88`）。二进制里"正好一半"是舍入位右侧 = `100…₂`。
10. **舍入会引发进位**：`1.111… → 10.000` 必须后规格化（右移一位、指数加 1），否则格式被破坏。
11. **`float`/`double` → `int` 越界或 NaN 是未定义行为**（常常静默变成 `TMin`），不要依赖它的结果。
