# datalab 位级洞察记录

> 配套 `README.md`（实验记录与分数）。这里只记**想通了什么**，不重复代码。
> 全部结论都经过 `./dlc bits.c`（静默）+ `./driver.pl`（62/62）验证。

## 一、整数题：三个反复出现的套路

| 套路 | 本质 | 出现在 |
| --- | --- | --- |
| **德摩根律** | `x \| y == ~(~x & ~y)`、`x & y == ~(~x \| ~y)` —— 用一组运算符拼出另一组 | `bitXor`（只给 `~ &`，逼你造 `\|`） |
| **大常量靠移位拼** | 常数不许超过 8 位（`0xFF`），`0xAAAAAAAA` 得从 `0xAA` 左移 8、16 位拼出来 | `allOddBits`、`tmin` |
| **`<<31 >>31` 造掩码** | 一个 0/1 变成全 0 / 全 1。比 `-(!!x)` 好，因为整数题里没有负号可用 | `conditional` |

**判断"相等"的通用手法**：`!(a ^ b)`。异或会把不同位点亮，取逻辑非就得到"完全相同"。
`allOddBits` 用它比对掩码，`isTmax` 用它比对 `x+1` 与 `~x`。

## 二、逐题：卡在哪、怎么过的

### bitXor（`~ &`，7/14 ops）

`x^y` 的语义是"两位不同时为 1"。先想清楚 `x|y` 与 `x&y` 的关系：
`x^y = (x|y) & ~(x&y)` —— 至少一个为 1，但不是两个都为 1。
手上没有 `|`，用德摩根换成 `~(~x & ~y)`，一共 3 个 `~` + 3 个 `&`。

> 这题的意义不在答案，在于**证明"受限运算符也能表达任意布尔函数"**。

### tmin（1/4 ops）

`TMin = -2^31 = 0x80000000`。字面量不许写这么大，所以 `1 << 31`。
注意 `1 << 31` 在 C 里是未定义行为（有符号溢出），但在本题约定的 32 位补码机器上就是 `0x80000000`。

### isTmax（8/10 ops）

`TMax = 0x7FFFFFFF`，直接比对没法写（常量超 8 位）。找它的**代数特征**：
`x + 1 == ~x` 只在 `x == TMax` 时成立。

**但有个陷阱**：`x == -1` 时 `x+1 == 0`、`~x == 0`，也满足 `!((x+1) ^ ~x)`。
所以必须补一个 `!!(x + 1)` 排除 `-1`（它的 `x+1` 是 0）。这一题的教训是：
**代数恒等式往往有第二个解，要专门找出来排掉。**

### allOddBits（7/12 ops）

先造掩码 `0xAAAAAAAA`：`0xAA` → `| (mask<<8)` → `| (mask<<16)`。
再用"全等"手法 `!((x & mask) ^ mask)`。

### negate（2/5 ops）

补码取负的定义：`-x == ~x + 1`。这不是技巧，是 §2.3.3 的定义式，也是 **CPU 减法器的实现方式**。

### isAsciiDigit（9/15 ops）

区间 `0x30 <= x <= 0x39` 拆成两个"符号位测试"：

- `t = x - 0x30`，`t >= 0` ⟺ `t` 的符号位为 0 ⟺ `!(t >> 31)`
- `t < 10` ⟺ `t - 10 < 0` ⟺ `(t + ~9) >> 31` 的符号位为 1

**减法用 `+ ~y + 1` 表达**。这里的边界很干净：`t` 最大是 `0x39-0x30 = 9`，无论怎样都不会溢出到符号位。

### conditional（8/16 ops）

两个技术点：

1. `!!x` 把任意整数压成 0/1；
2. `(!!x << 31) >> 31` 把 0/1 摊成全 0 / 全 1（算术右移补符号位）。

然后 `(y & mask) | (z & ~mask)`：为 1 时 y 保留、z 被清零，反之亦然。
**这是无分支编程的原型**——CPU 里叫条件传送（`cmov`），消除了分支预测失败的代价。

> 我最初写的是 `-(!!x)`，`btest` 全过，但 `dlc` 直接报 `Illegal operator (-)`。
> 教训：**`btest` 只管结果对不对，"怎么写的"是 `dlc` 的职责，两条线都要过。**

### isLessOrEqual（15/24 ops）

最自然的想法：`y - x >= 0` ⟺ `!(z >> 31)`。**但正溢出会毁掉它**：
`y = TMax`、`x` 为负数时，`y - x` 溢出成负数，判断翻转。

所以必须**先看符号位再决定信不信这个差**：

| 情况 | 判断依据 |
| --- | --- |
| 两数同号 | 相减不会溢出，用 `z = y + ~x + 1` 的符号位 |
| 两数异号 | 减法无意义，直接看 `x` 是不是负数（是则 `x <= y`） |

用 `sameSign` 当选择掩码把两条路合起来，就是最终那个式子。

> **这是本题唯一真正的难点：溢出不是边界情况，是必须单独分支处理的语义分叉。**

### logicalNeg（6/12 ops）

题目禁止使用 `!`，要求手工实现它。核心是找"x 是否为 0"的位特征：

- `x == 0` → `x` 与 `-x` 都是 0 → `x | (~x+1)` 符号位为 0
- `x != 0` → `x` 与 `-x` 必有一个为负 → 符号位为 1

取出符号位再 `^ 1` 取反，就等价于 `!`，但一个 `!` 都没用。

### howManyBits（40/90 ops）

思路分两步：**负数取反成正数**（`y = x ^ (x >> 31)`，负数变成 `~x`），
然后二分找最高位的 1 在哪。

二分怎么写才不用 `if`？把"判断"变成"位移量"：

```c
hasHigh = !!(y >> 16);      // 高 16 位有 1 吗 → 0 或 1
count  += hasHigh << 4;     // 有就加 16
y     >>= hasHigh << 4;     // 有就把高 16 位移下来
```

16 → 8 → 4 → 2 → 1 走五轮，最后 `count + 1 + (y & 1)` 补上符号位。
`<< 4` 就是"乘以 16"的位级写法，也是本题省运算符的关键。

> 40 个运算符看着多，但上限是 90，够宽松——**这题考的是思路，不是抠运算符**。

## 三、浮点题：全是 IEEE 754 的位域拆装

```
 31   30        23 22                    0
+----+------------+----------------------+
| 符号|  阶码 e(8)  |      尾数 f(23)       |
+----+------------+----------------------+
```

- `e == 255` → Inf / NaN
- `e == 0` → 零或非规格化数（**没有隐含的前导 1**）
- 否则规格化数，真值 = `(1.f) × 2^(e-127)`

### floatScale2（12/30 ops）

乘 2 就是指数加 1，但要分四段：

| 输入 | 做法 |
| --- | --- |
| Inf / NaN | 原样返回 |
| **±0.0** | **直接返回**（单独一段，见下） |
| 规格化（e>0） | `uf + (1 << 23)` —— 给阶码字段加 1 |
| 非规格化（e==0） | 左移，但要**保住符号位** |

**两个符号位陷阱**（我都踩了）：

1. `-0.0` 是 `0x80000000`，`<< 1` 得到 `0` —— 符号位被移丢，`-0.0` 变成了 `+0.0`；
2. `-0x00000001`（最小负数非规格化数）是 `0x80000001`，`<< 1` 得到 `2` —— 同样丢符号。

统一修法：`((uf & 0x7FFFFFFF) << 1) | (uf & 0x80000000)` —— 只移低 31 位，符号位单独抬回 bit31。

> 参考实现（`tests.c` 的 `test_floatScale2`）用真正的 `float` 乘法 `2*f`，所以 `2 * -0.0 == -0.0`，
> 符号位必须保留。**别用"左移就够了"的直觉糊弄边界。**

### floatFloat2Int（18/30 ops）

`E = e - 127`，然后：

- `E < 0` → `|f| < 1` → 截断成 0
- `E >= 31` → 超出 `int` 范围（含 Inf/NaN）→ 返回题目指定的哨兵 `0x80000000`
- `E <= 23` → 尾数右移 `23-E` 位（小数位丢掉，即**向零截断**）
- `E > 23` → 尾数左移 `E-23` 位
- 最后按符号位取负

> 这题的坑不在算法，在 **`dlc` 的 C89 声明规则**：`int E = ...` 写在 `if` 后面，
> 一次性报了 14 条 `parse error` 和 `undeclared variable`。
> 声明必须全部集中在函数体开头。

### floatPower2（9/30 ops）

`2.0^x` 的结果位模式非常有规律，按区间直接写出来就行：

| x 范围 | 结果 | 位模式 |
| --- | --- | --- |
| `x >= 128` | `+INF` | `0x7F800000` |
| `-126 <= x <= 127` | 规格化 | `(x + 127) << 23` |
| `-149 <= x <= -127` | 非规格化 | `1 << (x + 149)` |
| `x < -149` | 太小，下溢 | `0` |

`x + 149` 是推导出来的：非规格化数的最小指数是 `2^-126`，尾数最低位代表 `2^-149`。

## 四、可复用的结论

1. **`btest` 和 `dlc` 管的是两件事**：前者管结果，后者管写法。任何一关不过，该题都是 0 分。
2. **编译失败时 `btest` 会安静地测旧二进制**，给出一个看起来正常的分数。这是最危险的一类假信号。
3. **代数恒等式要找反例**（`isTmax` 的 `-1`）；**减法要防溢出**（`isLessOrEqual`）；
   **移位要看符号位去哪了**（`floatScale2`）。这三条覆盖了本 lab 绝大多数错解。
4. **常数 ≤ 8 位** 这条限制不是刁难，它逼你理解"掩码是怎么构造出来的"——这正是位运算的基本功。
