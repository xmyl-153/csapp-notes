## 一、题目分类

datalab 的 13 道题按类型分三张表：

**表 1 · 位级操作**

| 函数 | 要求 |
| --- | --- |
| `bitXor(x,y)` | 只用 `&` 和 `~` 实现 `x ^ y` |
| `allOddBits(x)` | 所有奇数位是否都置为 1？ |
| `isAsciiDigit(x)` | x 是不是一个 ASCII 数字？ |
| `conditional(x, y, z)` | 等价于 C 的 `x ? y : z` |
| `logicalNeg(x)` | 不使用 `!` 运算符计算 `!x` |

**表 2 · 补码算术**

| 函数 | 要求 |
| --- | --- |
| `tmin()` | 返回最小的补码整数 |
| `isTmax(x)` | x 是不是最大的 32 位补码整数？ |
| `negate(x)` | 不用负号求 `-x` |
| `isLessOrEqual(x,y)` | `x <= y`？ |
| `howManyBits(x)` | 表示 x 最少需要多少位？ |

**表 3 · 浮点**（f 的位模式与 `unsigned uf` 相同）

| 本 handout 的题 | 要求 |
| --- | --- |
| `floatScale2(uf)` | 计算 `2.0*f` |
| `floatFloat2Int(uf)` | 计算 `(int) f` |
| `floatPower2(x)` | 计算 `2.0^x` |

> 官方 PDF 的表 3 写的是 `float_twice` / `float_f2i` / `float_i2f`，但**这份 2019 handout 没有 `float_i2f`**，第三题是 `floatPower2`。以 `bits.c` 注释为准。

## 二、贯穿全程的五个套路

**1. 大常数不许写，靠移位拼。**
常数上限是 8 位（`0xFF`），`0xAAAAAAAA` 这种得从 `0xAA` 移出来：

```c
int mask = 0xAA;
mask = mask | (mask << 8);    // 0xAAAA
mask = mask | (mask << 16);   // 0xAAAAAAAA
```

**2. 判断"相等"用 `!(a ^ b)`。**
异或会把不同的位点亮，逻辑非之后就是"完全没有差异"。
`allOddBits` 拿它比对掩码，`isTmax` 拿它比对 `x + 1` 与 `~x`。

**3. 判断"是否为 0"，看 `x | (~x + 1)` 的符号位。**

- `x == 0` → `x` 和 `-x` 都是 0 → `x | (~x+1)` 的符号位是 **0**
- `x != 0` → `x` 与 `-x` 必有一个为负 → 符号位是 **1**

即 `iszero = !((x | (~x+1)) >> 31)`。正数和 0 的符号位都是 0，所以这一招**只区分 0 与非 0**，不区分正负。

**4. 完全右移 `>> 31` 是一个"取符号位"的工具。**
右移 31 次后，原来的 32 位只剩最高位，其余全被移出，而且补进来的是符号位：

```
正数/零：x >> 31 = 0000 ... 0000 = 0
负数　：x >> 31 = 1111 ... 1111 = -1
```

用它既能判正负（得 0 或 -1），也能造全 0 / 全 1 掩码。

**5. 造掩码不要用负号，用 `<< 31 >> 31`。**
`(!!x << 31) >> 31`：`!!x` 把任意整数压成 0/1，左移 31 位再算术右移回来，就摊成全 0 或全 1。
比 `-(!!x)` 稳——**减号根本不在合法运算符表里**，dlc 会直接报 `Illegal operator (-)`（我踩过）。

补码规则：

| `!!x` | 期望的掩码 | 用 `-(!!x)`（不许用） | 用 `(!!x << 31) >> 31`（可以） |
| --- | --- | --- | --- |
| `0` | 全 0 | `0x00000000` | `0x00000000` |
| `1` | 全 1 | `0xFFFFFFFF` | `0xFFFFFFFF` |

## 三、逐题思路

### ② allOddBits（Rating 2，7/12 ops）

目标：一个"奇数位全 1"的掩码，再看原输入和它是否处处相等。
限制：不能写等号直接比，也不能一次写出多个 `A`。

```c
int mask = 0xAA;
mask = mask | (mask << 8);
mask = mask | (mask << 16);
return !((x & mask) ^ mask);     // 没有差异 = 相等
```

### ③ isAsciiDigit（Rating 3，9/15 ops）

**怎么表示一个范围？下界和上界的逻辑与。**

两种手段要分清（这是这题真正的收获）：

- **边界问题 / 数值问题 → 减法更简洁**（内部的位一直在变，没法用固定掩码描述）
- **位匹配问题 → 掩码匹配**

范围 `0x30 <= x <= 0x39` 拆成两个符号位判断：

```c
int t = x + ~0x30 + 1;          // t = x - 0x30（不能写减号，用 + ~y + 1）
int geLower = !(t >> 31);       // t >= 0：符号位是 0
int leUpper = ((t + ~10) >> 31); // t < 10：符号位是 1
return geLower & leUpper;
```

上界这里有个**差 1 的坑**：`t <= 9` 要写成 `t < 10`，即 `t - 10 < 0`。
而补码里 `~y == -y - 1`，所以 **`-10 = ~10 + 1`，不是 `~9`**：

- 想写 `-10`，要么 `+ ~9 + 1`，要么 `+ ~10`；
- **`t + ~9` 实际等于 `t - 9`**，直接用会差 1（我原来的笔记就写错了，这里已经改过来）。

### ④ conditional（Rating 3，8/16 ops）

`x` 的真假决定返回 `y` 还是 `z`。掩码要满足"全 0 或全 1"：

- 输入是任意整数 → 先用 `!!x` 压成 0/1；
- 需要的是掩码 → 用移位摊开（见套路 5）。

```c
int mask = (!!x << 31) >> 31;
return (y & mask) | (z & ~mask);   // 掩码为 1 时留下 y，为 0 时留下 z
```

还有更省运算符的异或版本：`return y ^ ((y ^ z) & mask);`（这题两种写法都在上限内，我用了前者，更好读）。

### ⑤ logicalNeg（Rating 4，6/12 ops）

题目禁止使用 `!`，要求手工实现它。用套路 3 找"是否为 0"，再取反：

```c
return (((x | (~x + 1)) >> 31) & 1) ^ 1;
```

`>> 31 & 1` 把 -1/0 变成 1/0，最后 `^ 1` 取反。全程没写一个 `!`。

### ① tmin（Rating 1，1/4 ops）

所有 `int` 都是补码，所以"最小的补码整数"就是 `int` 的负半轴最远处：`-2^31`。

我原来的想法：**要得到最高位为 1 的数，对一个干净的 1 左移 31 位**——
关键在于"位级视野"：这个数不是"算"出来的，是**摆**出来的。

```c
return 1 << 31;     // 0x80000000
```

### ② isTmax（Rating 1，8/10 ops）

最大值 `2^31 - 1 = 0x7FFFFFFF`，二进制 `0111 ... 1111`。最小值好表示，最大值不好表示，
但可以用它的**关系式**：`x + 1 == ~x`（最大的反码正好是最小）。

```c
return !((x + 1) ^ ~x) & !!(x + 1);
```

**这里有个溢出造成的起点混淆**：`x == -1` 时 `x + 1 == 0`、`~x == 0`，也满足 `x + 1 == ~x`。
所以必须补一个 `!!(x + 1)` 把 `-1` 排除掉。三段式记法：**符合关系 & 排除溢出混淆**。

### ③ negate（Rating 2，2/5 ops）

补码的溢出规律就是负数最省事的表达：`-x = ~x + 1`。不用减号。

### ④ isLessOrEqual（Rating 3，15/24 ops）

我最初的想法很直接：

```c
int z = y - x;
return !(z >> 31);      // 不是负数就 <=
```

两个问题：**datalab 不让用减法**，而且**负减正的边界会溢出**，符号位翻转、判断就错了。

改成"先看符号，再决定信不信这个差"：

```c
int signX = (x >> 31) & 1;          // 符号位与 1 "刻印"，只留 0/1
int signY = (y >> 31) & 1;
int sameSign = !(signX ^ signY);    // 有差异 = 1，取非后同号为 1
int z = y + ~x + 1;                 // 做差：y - x
int sameSignResult = !(z >> 31);
return (sameSign & sameSignResult) | ((!sameSign) & signX);
```

- **同号**：相减不会溢出 → 用做差结果（`sameSign & sameSignResult`）；
- **异号**：减法无意义 → 直接看 `x` 是不是负数（`(!sameSign) & signX`）。

用 0/1 的判断值当开关：为 0 时正好把另一半否定掉。

### ⑤ howManyBits（Rating 4，40/90 ops）

思路：**先把负数取反成正数**（`y = x ^ (x >> 31)`），再二分找最高位的 1 在哪，最后加符号位。

带 `if` 的版本（便于理解）：

```c
int y = x ^ (x >> 31);
int count = 0;
if (y >> 16) { count += 16; y >>= 16; }
if (y >> 8)  { count += 8;  y >>= 8;  }
if (y >> 4)  { count += 4;  y >>= 4;  }
if (y >> 2)  { count += 2;  y >>= 2;  }
if (y >> 1)  { count += 1;  y >>= 1;  }
return count + 1 + (y & 1);
```

**禁用 `if` 之后怎么改**：把"判断"变成"位移量"。

```c
int hasHigh = !!(y >> 16);   // 高 16 位有没有 1 → 0 或 1
count += hasHigh << 4;       // 有就加 16（16 = 1 << 4）
y >>= hasHigh << 4;          // 有就把高 16 位移下来
```

16 → 8 → 4 → 2 → 1 走五轮，最后 `count + 1 + (y & 1)`。

## 四、浮点：三个位域

```
 31   30        23 22                    0
+----+------------+----------------------+
| 符号 |  阶码 e(8)  |      尾数 f(23)      |
+----+------------+----------------------+
```

### ① floatScale2（Rating 4，12/30 ops）

乘 2 等价于**指数加 1**（因为 `2 = 2^1`），所以走按位加。分四种情况：

| 情况 | 处理 |
| --- | --- |
| 规格化（e 在 1~254） | 指数加 1 |
| 非规格化（e == 0） | 整体左移（没有隐含前导 1，只能靠移位） |
| 零（e == 0 且 f == 0） | 本身 |
| 无穷大 / NaN（e == 255） | 本身 |

写的时候**特殊分支放前面**：

```c
unsigned e = (uf >> 23) & 0xFF;
if (e == 255) return uf;                  // Inf / NaN
if ((uf & 0x7FFFFFFF) == 0) return uf;    // ±0
if (e > 0) return uf + (1 << 23);         // 规格化：指数加 1
return ((uf & 0x7FFFFFFF) << 1) | (uf & 0x80000000);  // 非规格化
```

**我自己踩的两个符号位坑**（都是左移惹的）：

- `-0.0` 是 `0x80000000`，`<< 1` 得到 `0` —— 符号位被移丢，`-0.0` 变 `+0.0`；
- `0x80000001`（最小负数非规格化数）`<< 1` 得到 `2` —— 同样丢符号。

修法统一是：**只移低 31 位，符号位单独抬回 bit31**。
（我原来写的 `if (e >= 1)` 漏掉了"e == 0 但符号位为 1"这一支，后来补上的。）

### ② floatFloat2Int（Rating 4，18/30 ops）

分支在于**是否超过 `int` 范围**，超了要返回题目指定的特殊值（含 NaN 和无穷）：

```c
int s = (uf >> 31) & 1;            // 符号位
int e = (uf >> 23) & 0xFF;         // 指数位
int f = uf & 0x7FFFFF;             // 尾数位
int E, mantissa, result;           // ← 声明必须集中在这里（见第六节）

if (e == 255) return 0x80000000;   // Inf / NaN
if (e == 0) return 0;              // 非规格化数 / ±0

E = e - 127;                       // 实际指数
if (E < 0) return 0;               // 小于 1，截断为 0
if (E >= 31) return 0x80000000;    // 超出 int 范围

mantissa = (1 << 23) | f;          // 1.f 的整数表示
if (E <= 23) result = mantissa >> (23 - E);   // 右移丢小数位
else         result = mantissa << (E - 23);   // 左移补零
if (s) result = -result;
return result;
```

### ③ floatPower2（Rating 4，9/30 ops）

`2.0^x` 的位模式按区间直接写：

| x 范围 | 结果 |
| --- | --- |
| `x >= 128` | `+INF`（`0x7F800000`） |
| `-126 <= x <= 127` | 规格化：`(x + 127) << 23` |
| `-149 <= x <= -127` | 非规格化：`1 << (x + 149)` |
| `x < -149` | 太小，返回 0 |

## 六、踩过的五个坑（全部由 `dlc` / `driver.pl` 抓出）

| # | 症状 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | `./btest` 报 27/36，但**这个分数是假的** | `bits.c` 有语法错误 → `make` 失败 → 测的是**上一次编译的旧二进制** | 先看 `make` 输出，有 `error` 就别看分数 |
| 2 | `dlc: conditional: Illegal operator (-)` | 用 `-isNonZero` 造全 1 掩码，**减号不在合法运算符里** | `int mask = (!!x << 31) >> 31;` |
| 3 | `dlc: logicalNeg: Illegal operator (!)` | 题目就是"不许用 `!` 实现 `!`"，原式第一个字符就是 `!` | `(((x \| (~x+1)) >> 31) & 1) ^ 1` |
| 4 | `floatFloat2Int` 连报 14 条 `parse error` / `undeclared variable` | 声明写在 `if` **之后**；`dlc` 只认 C89——块内所有声明必须在任何语句之前 | 把 `int E, mantissa, result;` 挪到函数体开头 |
| 5 | `floatScale2(-0.0)` 与非规格化负数算错 | 左移把符号位移丢（`0x80000000 << 1 == 0`） | ±0 单独返回；非规格化只移低 31 位、符号位单独抬回 |

**第 1 条最值得记**：编译失败时 `btest` 不报错，它安静地测旧二进制，给出一个看起来"还行"的分数。
这是唯一一个"工具本身没错、是你漏看了 `make` 输出"的坑。

**第 4 条最反直觉**：`btest` 全绿不代表写得合规。`btest` 管结果、`dlc` 管写法，两条线都得过。
